# Bun 1.4 versus Eido's Node/npm/Vite/Vitest toolchain: performance evidence

**Scope/date.** Point-in-time assessment on 2026-08-23 (web sources accessed 2026-08-22). I inspected Eido's `package.json`, `package-lock.json`, Vite and Playwright configs, CI workflows, `scripts/ci/required.mjs`, the Electron SQLite runtime, the OpenRouter streaming boundary, and the standalone C gateway helper. The current declared toolchain is Node `>=24 <25` (Volta `24.12.0`), npm `>=11 <12` (Volta/packageManager `11.6.2`), Vite `^8.0.16`, Vitest `^4.1.10`, Electron `43.2.0`, and Playwright `^1.62.0`. The lockfile has 763 package entries and the manifest has 30 direct dependencies/dev-dependencies. No `node_modules`, Bun executable, or Electron executable is present in this worktree, so no dependency install, app build, Profile access, or Bun run was attempted.

## Baselines and source quality

Bun's public benchmark source is in [`oven-sh/bun/bench`](https://github.com/oven-sh/bun/tree/main/bench), and Bun recommends `hyperfine` for scripts/CLI and `mitata` for microbenchmarks ([methodology](https://bun.com/docs/project/benchmarking), accessed 2026-08-22). The strongest quantitative source is Bun's own v1.4 landing page: install numbers use a T3 Next app (25 direct dependencies, about 220 lockfile packages), Linux x64 AMD EPYC 9R14, package-manager defaults, prepared state per scenario, and medians of three runs ([benchmark page](https://bun.com/), accessed 2026-08-22). These are useful directional bounds, not Eido measurements. Bun's release post is dated August 20, 2026 ([release notes](https://bun.com/blog/bun-v1.4)).

One cheap local read-only check used the host's pinned runtime: `Darwin 25.5.0 arm64`, Mac16,13, 10 cores, 24 GB RAM, macOS 26.5, Node 24.12.0, npm 11.6.2. Thirty `spawnSync(process.execPath, ['-e',''])` launches measured p50 **95.7 ms** and p90 **338.7 ms** (min 55.5 ms, max 762.6 ms). `/usr/bin/time -l npm run ci:runtime --silent` measured **0.26 s real**, **72,237,056 bytes maximum RSS**. These are host-specific observations, not Node-vs-Bun comparisons.

## Slowdown and adoption risks

The largest risk is not speed: Bun 1.4 is recent and its Node compatibility is improving rather than complete. The macOS arm64 v1.4.0 probe resolves basic `node:sqlite` API presence for that released artifact, but does not establish WAL, `synchronous=FULL`, locking, backup, recovery, or performance parity; the current API reference remains inconsistent and should be treated as documentation drift or a version mismatch. Bun reports 97% pass rates for several Node module suites and 100% for `node:sqlite` in its vendored tests, but those are not Eido's revision-store proof. Bun's package-lock migration also creates a new `bun.lock` and CI policy, while Eido currently enforces npm and calls `npm ci` inside the canonical gate. Vite custom plugin behavior, Vitest fork/coverage semantics, Electron's fixed ABI, and macOS/Windows native helper packaging are all potential regressions. A slowdown is plausible when Bun's compatibility layer, lock migration, or plugin transforms add work; vendor headline ratios do not justify changing the packaged Electron/SQLite runtime.

**Recommendation.** Treat Bun 1.4 as a bounded install/script/CI experiment. Do not forecast whole-app, Electron-startup, AI-latency, or SQLite gains. A useful disposable spike must compare npm and Bun on the same Eido revision, exact Node/Bun versions, cold/warm registries, lockfiles, `npm run build`, `npm test`, Playwright health, four Electron Vite modes, synthetic SQLite WAL/read/write/backup fixtures, and RSS. No real Profile is required or appropriate.
