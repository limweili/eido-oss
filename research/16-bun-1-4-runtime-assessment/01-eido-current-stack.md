# Eido current stack and Bun 1.4 replacement map

## Scope and method

This is source/config inspection only; no Profile was opened or copied. I inspected `package.json`, `package-lock.json`, TypeScript/Vite/Electron configs, CI and release workflows, Electron entry points, persistence/SQLite, AI execution, canvas rendering, native helper scripts, and the relevant foundation/ADR documents. File/line references are to the inspected worktree. The lockfile is authoritative for resolved versions; `node_modules` is absent in this worktree, so I did not infer runtime success from an install.

## Facts: named technology inventory

* **Authoritative toolchain:** Node `24.12.0`, npm `11.6.2`, with `packageManager: npm@11.6.2`, engines `node >=24 <25`, `npm >=11 <12`, and matching Volta/devEngines declarations (`package.json:1-26`). `package-lock.json` is lockfile v3 (`package-lock.json:1-8`).
* **Browser application:** React `18.3.1`, React DOM `18.3.1`, `@xyflow/react` (declared `^12.3.5`, lock resolves `12.11.0`), Zustand, Immer, MDXEditor, PrismJS, Lucide, nanoid, tldts, and zip.js (`package.json:65-79`). Canvas rendering is React Flow plus an HTML canvas overview layer (`src/canvas/Board.tsx:1-18,3905-4009`; `src/canvas/BoardOverviewLayer.tsx:515-737`; `src/canvas/boardScene.ts:680-921`).
* **Build/development:** TypeScript (declared `^5.6.3`, lock `5.9.3`), Vite `8.0.16`, `@vitejs/plugin-react 6.0.2`, Vitest `4.1.10`, jsdom `29.1.1`, Testing Library packages, and Playwright `1.62.0` (`package.json:81-97`; `tsconfig*.json`; `vite.config.ts:1-40`). Browser interaction, production, and performance suites are Playwright web servers, not Vitest (`playwright.*.config.ts`).
* **Desktop/release:** Electron `43.2.0`, electron-updater `6.8.9`, electron-builder `26.15.3`, Electron fuses `2.1.3`, and postject (`package.json:73,89-96`; `electron-builder.yml:1-38`). Four Vite Electron modes emit CommonJS `main.cjs`, `profile-utility.cjs`, `preload.cjs`, and `eido-cli-sea.cjs`, externalizing Electron and Node built-ins and disabling code splitting (`vite.electron.config.ts:1-66`).
* **Persistence:** the browser-dev path uses IndexedDB (`src/graph/save.ts:126-184`), while packaged Eido uses a single Electron utility-process SQLite owner. `electron/sqliteRuntime.ts:1-3,66-79,101-127,142-236,419-478` uses Node's synchronous `node:sqlite` `DatabaseSync`/`backup`, WAL and defensive pragmas, exclusive ownership, synchronous transactions, checkpoints, integrity checks, and backups. The persistence foundation says the renderer receives neither SQL nor a storage path (`docs/foundations/persistence-layer.md:1-24,55-68`); ADR 0029 makes the one-utility-process boundary explicit (`docs/adr/0029-electron-main-installs-one-profile-authority.md:1-29`). A coordinator probe of the official Bun `1.4.0` macOS arm64 release successfully imported `DatabaseSync` from `node:sqlite` and returned `42` from an in-memory insert/select; this establishes basic API presence, not Profile safety.
* **AI/execution:** ordinary conversation execution is `src/brain/conversationRunner.ts:130-381`, with graph-derived run artifacts and `runEngine.ts:189-220`. Provider traffic is browser/renderer `fetch` to OpenRouter SSE (`src/brain/openRouter.ts:38,433-641`). Electron main owns delegated/local harnesses and process routing. MCP uses `@modelcontextprotocol/sdk 1.30.0` and stdio (`electron/profileMcpServer.ts` symbol `createProfileMcpServer`; `electron/main.ts:770-834`).
* **Native/packaging:** the live Profile gateway is C11 compiled with clang on macOS or MSVC on Windows (`scripts/electron/profile-live-gateway-helper.mjs:17-181`; `native/profile-live-gateway/*`). Packaged standalone CLI uses Node SEA, postject, signing, and an exact Volta-derived Node version (`scripts/electron/profile-mcp-sea-after-pack.mjs:1-30,39-205`). Electron builder runs the after-pack hook and preserves fuses/asar invariants (`electron-builder.yml:1-38`).

## Facts: process and runtime topology

The GUI enters Electron (`electron/main.ts`), creates a BrowserWindow and secure preload after `app.whenReady` (`electron/main.ts:261-336`), and exposes capability-scoped APIs through `contextBridge`/IPC (`electron/preload.ts:1-123`). Main starts the installed Profile utility with `utilityProcess.fork(.../profile-utility.cjs)` (`electron/main.ts:867-889`); `electron/profileUtilityEntry.ts:1-75` serves the parent-port request queue. Main also starts the local live gateway helper on macOS/Windows (`electron/main.ts:891-929`). Headless JSON/CLI/MCP launch modes route through the packaged Electron executable; Windows MCP uses dedicated pipes and a package-owned SEA relay (`electron/main.ts:770-834`; `electron/eidoCliStandalone.ts:311-407`; ADR 0029:17-29 and ADR 0031:21-60).

Vite is both browser bundler and development/preview server. Custom plugins install Connect middleware for `/api/eido` JSON disk storage and link previews, plus virtual token CSS/license assets (`scripts/vite/storagePlugin.ts:1-160`; `scripts/vite/linkPreviewPlugin.ts:1-40`; `scripts/vite/designTokensPlugin.ts:1-71`). Packaged persistence is not this server: `profileRendererPersistence.ts:408-433` and `src/main.tsx:39-127` fail closed unless the installed bridge is present.

## Candidate Bun seams (current technology, verdict, and reason)

| Candidate | Current replacement target | Verdict |
|---|---|---|
| Package manager | npm 11 + `package-lock.json` | **Real, but policy-blocked.** Bun can consume an npm lockfile and install Node-compatible `node_modules` ([Bun lockfile docs](https://bun.sh/docs/pm/lockfile)); however this repository requires exact npm metadata and npm behavior. `scripts/ci/toolchain-policy.mjs:1-10,104-158,174-190,244-319` rejects a non-npm declaration, requires every script's npm runtime guard, and `scripts/ci/required.mjs:6-63` requires `npm_execpath` and invokes npm. CI caches/installs npm (`.github/workflows/ci.yml:57-81`). A Bun PM experiment is feasible; authoritative replacement requires policy, lockfile, CI, and release proof changes. |
| Script runner | `npm run` | **Real only for selected local scripts.** Bun documents `npm run` ↔ `bun run`, but guarded scripts start `npm run ci:runtime --silent &&` (`toolchain-policy.mjs:1-10`). Running the guard under Bun makes `npm_config_user_agent`, `npm_execpath`, and exact-version checks fail. Explicit `node` commands also intentionally select Node, and `process.execPath` is used by SEA/native proofs. |
| Unit test runner | Vitest + jsdom/Testing Library | **Not a drop-in seam.** Tests import Vitest APIs and Vite supplies the test config (`vite.config.ts:1-40`); browser suites remain Playwright. Bun's `node:test` compatibility is partial and `bun:test` would require imports/config migration. Native proof explicitly invokes `node_modules/vitest/vitest.mjs` through `process.execPath` (`scripts/electron/profile-live-gateway-native-proof.mjs:6-81`). |
| Browser bundler | Vite 8 + React/Vite plugins | **Irrelevant/high-cost.** Vite plugins provide Connect middleware, virtual modules, generated assets, and manual chunks (`vite.config.ts:1-40`; `scripts/vite/*`). Bun's bundler would need these rebuilt. For Electron, current four-mode CommonJS output is a hard boundary: Bun documents that `format: 'cjs'` with Bun target emits a special wrapper incompatible with Node ([Bun bundler docs](https://bun.sh/docs/bundler)). |
| Dev/preview server | Vite Connect server | **Real in theory, not packaged runtime.** Bun.serve could replace the `/api/eido` development server after rewriting Vite middleware/HMR/preview integration. It cannot replace the installed Profile bridge; packaged mode intentionally fails closed without Electron IPC (`profileRendererPersistence.ts:408-433`). |
| SQLite/Profile runtime | Node 24's `node:sqlite` in Electron utility process | **API seam is real; safe migration is unverified.** The coordinator's exact Bun `1.4.0` macOS arm64 probe imported `DatabaseSync` from `node:sqlite` and successfully created/inserted/selected an in-memory row (`42`), so the basic Eido import/API shape exists. Eido still depends on exact transaction behavior, WAL and synchronous pragmas, defensive/security options, backup, recovery, exclusive/concurrent ownership, and the ADR-mandated utility-process boundary. Those Bun 1.4.0 semantics, especially packaged utility behavior, remain unverified; this is not yet authority to replace Node/Electron SQLite. |
| Desktop shell | Electron | **Impossible/irrelevant as a direct swap.** Bun has no BrowserWindow/Chromium, preload/contextBridge, Electron IPC, `utilityProcess`, app lifecycle, updater, asar, or fuses. Replacing Electron is a new desktop architecture, not Bun adoption. |
| SEA/CLI/release | Node SEA + postject + electron-builder | **Not a drop-in seam.** `afterPack` requires exact Node `process.version`, injects the Node SEA blob, signs artifacts, and coordinates the native relay (`profile-mcp-sea-after-pack.mjs:39-205`). Bun's executable/compile path does not produce the required Node SEA artifact or preserve Electron's launch topology. |
| Native helper | clang/MSVC C gateway | **Outside Bun's replacement scope.** Bun could launch a compiler, but cannot replace C11 OS socket/named-pipe code, Windows security probes, codesigning, or platform-specific process semantics. |
| AI/canvas/browser tests | OpenRouter SSE, DOM/canvas, Playwright | **Irrelevant to runtime swap.** These execute in the renderer or external browser. Bun could host an optional tool, but moving provider egress or canvas execution would change security and product boundaries. |

## Dependencies, failure cases, and implications

The hard native/runtime boundary is SQLite plus Electron utility-process ownership. A direct `bun run build` or `bun test` will encounter npm policy, Vitest/config, and explicit Node assumptions before product behavior is proven. A direct Bun bundler migration risks Node-incompatible CommonJS Electron entries. Bun 1.4.0 now has the basic `node:sqlite` API shape, but transaction, WAL, synchronous-pragma, packaged-utility, recovery, and concurrency semantics remain unverified; replacing the current runtime still requires a fresh persistence/packaged certification proof. A Bun desktop replacement loses the BrowserWindow/preload/utility-process contract. Bun's partial Node compatibility also leaves child-process, module, HTTP, and test-runner edge cases requiring targeted proof, even where a script appears syntactically runnable.

**Recommendation (inference):** treat Bun 1.4 as a bounded developer-tool experiment: optionally benchmark Bun's npm-compatible installer or run isolated, non-authoritative scripts while retaining npm, Node 24, Vite, Vitest, Electron, electron-builder, Node SEA, and the existing lockfile as release authority. Do not claim Bun runtime adoption for Eido until a new ADR and disposable packaged proof cover `node:sqlite` API parity plus transaction/WAL/pragma/backup/recovery/concurrency semantics, utility-process ownership, Electron CJS outputs, native gateway/SEA packaging, CI policy, and cross-platform certification. The unresolved high-impact question is no longer whether Bun 1.4 exposes `node:sqlite`; it is whether the observed API can preserve every current Profile authority invariant under packaged and concurrent workloads.
