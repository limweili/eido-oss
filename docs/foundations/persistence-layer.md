# Local Profile Persistence Boundary

The Local Profile Service is the logical authority boundary between Eido's graph and every storage or agent transport adapter. It preserves the renderer-facing Board meaning while allowing the physical persistence design to change behind one contract. This boundary supports Eido's three graph projections; it is not a fourth projection. Governing decisions: ADR 0016, ADR 0025, ADR 0026, ADR 0027, ADR 0029, ADR 0030 (single-class Mods), ADR 0031 (live Agent routing), and ADR 0040 (content fails closed, settings fail soft). Before persisting a new field on any record, follow [`docs/agents/persisting-a-new-setting.md`](../agents/persisting-a-new-setting.md): it decides content against setting, names the envelope, and states the proof required before merge.

Current single-class Mod persistence starts at physical record axis 2. Ordinary
read and Portable import still require axis 2. Installed shipped axis-1 Profiles
have one copy-first automatic recovery path: retain all adjacent Board meaning,
drop retired v1 Mod templates/controllers under ADR 0030, and publish a new axis-2
authority. There is no dual live reader or Mod translation path.

### Card authorship

GUI and Agent Card commits derive authorship inside the trusted persistence boundary. GUI commits use the owner session; Agent commits receive a call-scoped `client`/`sessionId` from the admitted internal connection and persist it in canonical revision request evidence. Caller command JSON and renderer-submitted Card or historical-Intent stamps cannot choose these fields. New Cards receive both actors, changed legacy Cards receive only `lastModifiedBy`, and unchanged or imported legacy Cards are not backfilled. Under the current surface, a Card's logical meaning includes its payload and owned child records; a Group additionally owns the ordered IDs of its current members, while top-level Board Card ordinals are container bookkeeping. This keeps native attribution aligned with user-visible edits: membership transfers stamp both old and new Groups, actual layer changes stamp every displaced Card, and unrelated reindexing or member motion inside an unchanged Group stamps neither. Persisted Agent surfaces v1/v2 retain their original ordinal-sensitive, pre-Group-membership attribution meaning for exact replay; v3 and later adopt the current rule. Deletion is an ordinary user engagement before the undo base is captured. Newly appended create/delete Intent snapshots have their embedded authorship rebuilt from native-owned current or stamped target state, so a later undo revival preserves the durable creator, records the user as last writer, and cannot elevate forged renderer provenance. This is additive logical payload data, not a physical SQLite schema migration.

## Invariants (do not break)

1. **Logical data is the contract; physical storage is hidden.** Renderer and gateway consumers depend on logical records and `SavedBoard`, never SQL, paths, WAL layout, Electron IPC, or adapter-specific tables (ADR 0025).
2. **One validated mutation funnel owns durable change.** A command batch is optimistic, atomic, idempotent, attributed, and either advances one coherent Profile revision or preserves the prior revision (ADR 0016, ADR 0026).
3. **At most one mutable owner exists.** Authority is the continuously held exclusive sidecar handle plus its private monotonic token/generation fence, never a public owner ID, PID, heartbeat, timeout, or pathname alone. Persisted device number is only mount-local evidence; a device-only remount rebind requires the same inode/birth time plus full trusted Profile validation under that exclusive handle. A second writer receives stable `busy`; a stale expected revision receives `conflict`. Neither path edits concurrently or partially.
4. **Every compatibility dimension is explicit.** Profile, schema, record, asset, app, command, and export versions are all required and refuse unsupported future values instead of normalizing them down. For the current physical schema, an existing head's seven axes are read and validated before any Profile-schema write. A structurally different future physical format fails closed; classifying it precisely requires a future format-discovery contract rather than guessing from today's tables. This invariant governs the version axes and content shape only. It is explicitly scoped to exclude per-key values inside a record's settings envelope, which invariant 15 owns (ADR 0040).
5. **Stable logical identity survives storage changes.** Record IDs and references survive revisions and Portable Export/import; meaningful collection order remains domain order. A logical asset ID is distinct from its content digest.
6. **Mod templates and stamps have different owners.** Templates are versioned Profile records. Board instances are frozen, self-contained stamps with fresh stable nested IDs and never depend on a live template (ADR 0030). Record-axis-1 Mods are never translated: the bounded installed-Profile recovery drops them while preserving adjacent Board records; ordinary read and Portable import still refuse axis 1.
7. **The Agent Gateway is smaller than the internal action surface.** Surface v5 exposes only bounded Idea, Board/Connection, research-organization, and Mod commands, bounded inspection, and live-only Ask/Conversation delegation. Historical v1/v2/v3/v4 surfaces authorize exact replay only. MCP remains exact seven; CLI-only Idea/spatial/history/Run and ergonomic v5 operations cannot be guessed into it. Raw storage, SQL, filesystem, IPC, credentials, generic patch, provider output, and network-listener operations fail closed (ADR 0026).
8. **Secrets are outside the logical Profile.** API credentials, device-only secrets, physical paths, and unredacted diagnostics are absent from logical records, fixtures, gateway output, and Portable Export.
9. **Portable Export is logical and verifiable.** Full-Profile transfer contains a versioned manifest, logical record IDs including Profile-owned Agent events, and digest-verified asset closure; selected-Idea transfer excludes that Profile history. WAL, locks, caches, credentials, device settings, and derived indexes are explicit exclusions (ADR 0025).
10. **Semantic vectors remain absent and derived.** A future Semantic Index may be disposable and rebuildable, is excluded from authority/export by default, and cannot silently replace deterministic context policy (ADR 0027).
11. **Adapters agree where capabilities overlap.** SQLite, browser-development, in-memory, and fault-test adapters run the same observable conformance cases. Every operation advertised as available is callable; unsupported operations are declared, not approximated.
12. **Blob reachability and logical identity stay separate.** Cards order stable logical asset IDs; logical records carry immutable digest metadata; equal bytes deduplicate only physically. A revision cannot acknowledge a new reference before verified promotion, and removing the last live reference does not authorize final deletion until recovery and Portable Export roots are complete.
13. **Recovery never releases or rewinds authority.** The exclusive sidecar survives Profile quarantine/replacement. Its high-water advances before every acknowledged commit receipt; restore and automatic same-Profile repair reserve exactly one higher revision and bind the promoted head to their sidecar operation before normal admission resumes. Automatic repair first preserves unopened physical bytes and may discard invalid revision evidence only when the complete current logical projection still hydrates exactly. The one deliberate identity exception is the recovery-only manual start-fresh escape hatch (#813): it abandons the previous Profile authority by rebinding the trusted identity and high-water to a freshly seeded Profile — inside the sidecar transaction that completes its operation — while the abandoned bytes stay quarantined on disk.
14. **Portable publication changes evidence at bind.** A fresh import verifies operation-owned staged DB bytes only before physical binding. After `profile_owner_fence` opens the authority, acknowledgement and restart recovery prove SQLite integrity, the reserved canonical logical digest while still at the source revision, logical Profile identity/revision, and the complete streaming blob-root closure. A historical completed retry after legitimate later revisions verifies the current head and its current roots rather than requiring the old digest to remain current. WeakMap handles and the obsolete raw staged digest cannot stand in for durable sidecar evidence.
15. **Content fails closed; settings fail soft.** Every persisted field is one of three things. Content, meaning what the canvas, context, and execution projections read (ADR 0011), keeps the strict exact-key/exact-value validators and refuses anything unrecognized. A portable setting, meaning presentation or preference state that must travel with the Profile, lives in the owning record's additive settings envelope with a documented default: `Card.meta`, `Board.settings`, `Board.aiSettings`, which is now a tolerant preference bag rather than a strict one, `Idea.settings`, and Profile-level settings. An envelope is read tolerantly: an unrecognized key is preserved exactly as written through read and re-write; a recognized key whose value does not match this build's expected shape falls back to that setting's documented default, for that key alone; only a structurally invalid envelope, meaning one that is not a plain object, is corruption. A device setting, meaning state that only affects this machine and does not need to travel, stays in the device preference store and never enters the Profile document; it is the safest of the three and the preferred choice whenever a setting need not travel. An unrecognized setting key or value never fails a Card, Board, or Profile load, and adding or changing a setting never bumps a version axis (ADR 0040).
