## Active App Layout

| Path | Role | Notes |
| --- | --- | --- |
| `index.html` | Vite HTML entry and no-flash theme bootstrap | Resolves the device-only `eido-v3-settings` theme before loading `src/main.tsx`; invalid or missing values start Light. |
| `scripts/vite/designTokensPlugin.ts` | Vite design-token and font-license artifact plugin | Loads `src/ui/tokens.ts` into a virtual stylesheet and emits font provenance beside packaged assets. |
| `scripts/vite/storagePlugin.ts` | Vite dev/preview middleware for disk-backed Idea storage | Mounted by `vite.config.ts`; routes `/api/eido/**`. |
| `electron/` | Installed desktop Profile, Agent, and device-credential boundaries | Electron main selects exact bounded JSON or tools-only MCP mode before GUI startup, or pins the fixed installation and GUI singleton for normal rendering. One joined utility owns SQLite, revision/blob/recovery/portable work, and built-in template seeding; Electron main separately owns the versioned account-private local credential files, which hold OS-protected ciphertext rather than the key, and binds the OS protected-storage mechanism exactly once for the two user-supplied provider keys. Nothing reaches that mechanism until a credential file has actually been found on disk, so a launch that only opens Boards produces no system authorization prompt. The standalone `eido` SEA reaches the active owner over same-user tokened local IPC or uses the existing-only headless lease only after pre-admission absence. The exact frame receives disjoint typed Profile, credential, and delegated-Run bridges; live mutations pass the renderer barrier and delegated Runs pass the separate strict broker. Neither renderer nor caller input receives SQL, paths, owner credentials, transport choice, Gateway correlation authority, provider keys, model output, or browser-storage fallback. |
| `electron-builder.yml`, `vite.electron.config.ts`, `tsconfig.electron.json` | Desktop proof build configuration | Produces self-contained `main.cjs`, `profile-utility.cjs`, `preload.cjs`, and `eido-cli-sea.cjs` plus an unpacked ASAR-only, non-promotable package with reviewed fuses. Packaging builds the standalone `eido` SEA and native local-IPC helper on macOS arm64 and Windows x64. Windows also builds the strict-stdio `eido-profile-mcp.exe` SEA relay. Both SEAs embed the Node.js runtime used for packaging. The production macOS package declares a 13.5 minimum and lists both nested executables for signing. |
| `scripts/electron/profile-mcp-sea-after-pack.mjs` | Packaged SEA/native-entry hook | After pack and before signing, generates the standalone `eido` SEA plus native Live Gateway helper under the platform Resources `bin`; on Windows it also generates the transport-only x64 MCP console relay. The helper builder finds the installed VC x64 component with `vswhere`, captures `VsDevCmd`'s x64 environment, then invokes warning-as-error C11 MSVC. The MCP relay admits one exact flag, allowlists child environment, isolates request/protocol/diagnostic traffic on fd3/4/5, and drains rather than killing accepted work on signal or pump loss. |
| `native/profile-live-gateway/` | Same-user local IPC transport helper | Warning-clean C11 implementation for owner-only macOS Unix sockets and Windows named pipes. It verifies peer identity, relays length-prefixed frames without parsing Gateway JSON, bounds server reads with monotonic deadlines, and removes owned endpoints on stop or parent loss. |
| `scripts/electron/packaged-smoke.mjs` | Composed unpacked-package proof | Runs the disposable JSON/GUI/Agent journey, local credential migration/round-trip, delivered CSP and packaged endpoint inspection, verifies the platform MCP package entry, and records local persistent MCP as non-authoritative. On the required hosted ephemeral OS user only, it same-volume renames the closed synthetic Profile to the absent fixed root while preserving its SQLite/owner-sidecar physical identity, invokes the unmodified production MCP entry, and removes that owned root before writing one non-promotable evidence document. No local save participates. |
| `scripts/certification/` | Installed release-certification pipeline | Packages, installs, inspects, exercises, and pairs the sealed macOS arm64 and Windows x64 artifacts. The journey binds shipped GUI edits to the installed CLI/live route, spatial and change-history reads, live-only Run rejection, and exact-seven MCP compatibility. macOS inspection verifies plist identity, the 13.5 product floor, arm64 architecture, deployment targets, Developer ID/hardened/notarized posture, the embedded Squirrel `ShipIt` signature, and app-tree parity between the manual-install DMG and updater ZIP; Windows inspection verifies shortcut/AppUserModelID, PE architecture/version resources, and unsigned posture. |
| `scripts/electron/proof-host.mjs` | Native proof host helpers | Provides canonical filesystem-identity comparison and fail-closed, sequential Windows Authenticode inspection. |
| `src/electron-api.d.ts`, `src/types/electron-browser-boundary.d.ts` | Renderer-facing desktop types and root type quarantine | Exposes only the typed Profile, credential, local-harness, and delegated-Run preload bridges; keeps Playwright's optional Electron probe from importing Node-bearing desktop declarations into the root renderer program. |
| `src/main.tsx` | Persistence selection and React mount | Selects the required native adapter for packaged `eido://app` or the browser adapter for explicit trusted development, completes local credential migration, supplies the synchronous ready observer accepted after startup/recovery hydration, registers the app-scoped Agent Run runtime and drain-before-checkpoint handler, installs the packaged-safe numeric renderer-counter snapshot, then mounts the overlay/app providers. The fixture/reset performance runtime and graph-store global remain DEV-only. |
| `src/App.tsx` | App shell, recovery surface, top bar, Idea manager, empty state | Keeps normal mutable UI unmounted until native hydration is admitted; recovery-required startup exposes only inspection/restore before rehydrating the App. |
| `src/graph/` | Core graph model, Zustand store, local save/load, read-only helpers, timeline projection, and Profile Mod-origin integration | No React Flow imports observed in `types.ts`, `store.ts`, `save.ts`, `graphHelpers.ts`, `timeline.ts`, or `profileModOrigins.ts`. |
| `src/brain/` | Ask AI compiler/run engine, provider selection, delegated-Run contract/admission, Result follow-up runner, Conversation compiler/runner, source context freshness, OpenRouter/local-harness boundaries, ordered Mod prompt block, group digest, and provenance | `agentRunContract.ts`, `agentRunSession.ts`, `aiProvider.ts`, `aiProviderTypes.ts`, `compiler.ts`, `modBlock.ts`, `sourceContext.ts`, `followUpRunner.ts`, `conversationCompiler.ts`, `conversationRunner.ts`, `transcript.ts`, `runEngine.ts`, `openRouter.ts`, `groupDigestFreshness.ts`, `provenance.ts`. |
| `src/desktop/` | Renderer-side packaged adapters | Owns the live Agent mutation hold and delegated-Run bridge handler, app-scoped service/runtime, ordinary-Chain execution adapter, cancellation/drain, and persistence-flush boundary. No provider or SQLite implementation lives here. |
| `src/canvas/` | React Flow adapter, viewport-derived rendering, and UI cards/connections/modals | `Board.tsx`, `BottomDock.tsx`, cards, `ContextPeek.tsx`, `VersionContext.tsx`, shared `MarkdownPreview.tsx`, `SettingsModal.tsx`. |
| `src/canvas/cards/MarkdownCardEditor.tsx` | Selected-card Markdown editor boundary | Keeps a lightweight Markdown fallback during lazy loading, then delegates to `RichMarkdownEditor.tsx`; Note, Ask AI, and Conversation share this seam. |
| `src/canvas/boardScene.ts` | Cold scene and detail-band planner | Consumes viewport-independent card metrics; Reading plans visible visual DOM cards, while Overview/Map plan none. `mountPlanForScene` composes 0–2 invisible gesture proxies afterward. |
| `src/canvas/renderPlanning.ts` | Incremental spatial index and viewport render windows | Culls cards/connections, maintains position-aware grid state and position-blind label rank epochs, and exposes counted full-rebuild/cap fallbacks. |
| `src/canvas/cameraViewport.ts` | Immediate reduced-motion camera geometry | Mirrors React Flow's centering math and transform serialization so an intentional jump can bridge the exact store target to this Board's viewport before React Flow's deferred subscriber render. |
| `src/canvas/BoardOverviewLayer.tsx`, `labelLayer.ts`, `zoomChrome.ts` | Canvas shape/connection painting, screen-space labels, and shared chrome geometry | Map/Overview shapes use one band; labels apply priority/collision; port and badge paint/hit paths consume the same geometry owners. |
| `src/ui/primitives/` | Domain-free design-system control kit | Public exports come from `index.ts`; shared floating-layer arbitration and ref composition stay inside the module. Picker, Popover, Segmented, and Tooltip own their accessible interaction contracts here; `FloatingPortalScope` lets an owning overlay keep their portals inside its stack layer. |
| `src/ui/overlays/` | App-wide modal stack and async dialog service | `OverlayProvider` owns the single portal root, keyboard/focus/inert contract, scoped modal floating destinations, and FIFO confirm/prompt queue; `ModalShell` supplies the semantic frame and tokenized enter/exit presence. Public imports come from `index.ts`. |
| `src/ui/theme.ts`, `themeStore.ts`, `motion.ts` | Device appearance and motion seams | Keep theme preference separate from effective theme, subscribe to system media queries only when needed, apply document attributes, and expose the shared camera-duration and synchronous-jump policy. |
| `src/shared/` | Small cross-cutting helpers | `words.ts`, `ids.ts`, `markdown.ts`, `clipboardAssets.ts`, `linkPreview.ts`, `loadLinkPreview.ts`, `useAutoGrow.ts`. |
| `src/styles.css`, `src/styles/` | Ordered global style entry point and owned cascade modules | `src/main.tsx` imports the entry point; `000-foundation.css` establishes the base, `005-primitives.css` owns shared instrument recipes, `006-overlays.css` owns overlay/modal recipes, and numbered surface sheets follow. |

## Source Entry Points

| Flow | Entry | Downstream paths |
| --- | --- | --- |
| App boot | `src/main.tsx` | Installs numeric-only `window.__EIDO_RENDERER_COUNTERS__.snapshot()` in packaged and development builds, then mounts `OverlayProvider` -> `App`; the mutation-capable `window.__EIDO_PERF__` and graph-store `window.__eido` remain DEV-only. |
| Modal and async dialog presentation | `src/ui/overlays/index.ts` | Call sites render `ModalShell` or call `useDialogs`; `OverlayProvider` serializes requests and owns stacking, scoped floating layers, dismissal, inertness, exit retirement, and focus restoration. |
| Device appearance | `index.html`; `src/ui/themeStore.ts`; `src/ui/motion.ts` | Bootstrap Light/Dark/Match system without a flash -> apply document theme/motion attributes -> pass the effective theme explicitly through `App` to every live/playback `Board` and painter; the preference remains outside `SavedBoard`, snapshots, and exports. |
| Packaged hydration | `src/main.tsx` requires the installed preload sentinel/Profile bridge and structurally valid credential bridge; the exact link-preview bridge independently exposes bounded website load/recognition and opaque local-HTML recognize/load/open operations to the same owned frame | `src/graph/apiCredential.ts` completes successful legacy key migration and plaintext cleanup before render, but treats a valid bridge's storage failure as AI-unavailable rather than a Profile failure, and reports a credential the OS store would not open as locked rather than absent; `src/graph/profileRendererPersistence.ts` validates and pins the main-supplied `intentActorId` before the store applies the complete native snapshot/rebase; exact bridge ACK clears both admission fences, then the synchronous ready observer admits the store and normal `App`. `src/shared/loadLinkPreview.ts` selects the packaged preview bridge without widening Profile authority. Neither credential nor packaged actor identity persists in `localStorage` after successful migration. |
| Installed Agent CLI | packaged `eido` SEA | `electron/eidoCli.ts` plans bounded ergonomic commands -> `electron/eidoCliStandalone.ts` selects active-owner local IPC or proven-absence headless JSON -> `src/persistence/profileAgentGateway.ts` validates one descriptor/planner registry. MCP projects only its exact seven adapter-enabled tools. |
| Delegated Agent Run | `eido run` -> active packaged app | `electron/profileAgentRunRendererBroker.ts` correlates the exact frame -> `src/desktop/profileAgentRunRendererRuntime.ts` reserves the graph-derived Ask/Conversation budget -> `src/brain/agentRunExecutor.ts` revalidates and invokes exactly the admitted ordinary-run schedule for one output or 1–8 variations -> terminal status exposes bounded Run/output-version references. Authority loss/quit stops admission, cancels/drains accepted work and flushes, then allows the final renderer checkpoint. |
| Browser-development hydration | Explicit trusted browser development selects the legacy adapter | `src/graph/store.ts` -> `src/graph/save.ts` -> Vite disk API when available, else IndexedDB; the commit funnel retains its browser `localStorage` actor identity. Bridge absence outside this mode is terminal. |
| Canvas edits | `src/canvas/Board.tsx` | Translates React Flow nodes/edges to store actions in `src/graph/store.ts`. |
| Canvas scene/render | `src/canvas/Board.tsx` | `renderPlanning.ts` supplies the viewport window -> `boardScene.ts` chooses Reading/Overview/Map and mount routing -> `mountPlanForScene` adds gesture proxies -> React Flow and `BoardOverviewLayer.tsx` render the plan. |
| Timeline playback | `src/canvas/TimelinePlayback.tsx` | Uses `src/graph/timeline.ts` projections and playback-only rendering in `src/canvas/cards/PlaybackCard.tsx`. |
| Mod edit and library save | `src/canvas/cards/ModCard.tsx`; `src/mods/faces/`; `src/mods/chrome/` | Face interactions commit one current Mod document through the store. Packaged template hydration and stamping use authoritative native template records plus exact origin evidence. |
| AI run | `src/canvas/cards/AskAiCard.tsx` | `src/brain/runEngine.ts` -> `src/brain/compiler.ts` / `src/mods/prompt.ts` -> `src/brain/aiProvider.ts` -> OpenRouter fetch or `electron/aiHarnessMainSession.ts` -> store run/output actions and Mod provenance. |
| Result follow-up | `src/canvas/cards/ResultCard.tsx` | `src/brain/followUpRunner.ts` -> stored `RunRecord.compiledInstruction`/selected `OutputVersion` -> `src/brain/aiProvider.ts` -> store follow-up thread actions. |
| Conversation run | `src/canvas/cards/ConversationCard.tsx` | `src/brain/conversationRunner.ts` -> `src/brain/conversationCompiler.ts`/`transcript.ts` -> `src/brain/aiProvider.ts` -> store conversation run/output actions and room/participant Mod provenance. |
| Result provenance and source-change hints | `src/canvas/cards/ResultCard.tsx` and `src/canvas/cards/ConversationResultCard.tsx` | `src/canvas/VersionContext.tsx` reads stored run provenance and renders its content through the shared `MarkdownPreview.tsx`; `src/brain/sourceContext.ts` compares stored source fingerprints for the Source changed badge. |
| Group compression | `src/canvas/cards/GroupCard.tsx` | `src/brain/groupDigestFreshness.ts`; `src/brain/runEngine.ts` group digest path. |
