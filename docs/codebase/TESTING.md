## Rich Card Baseline Evidence

The issue-specific, manual `.github/workflows/rich-card-baseline.yml` experimental workflow runs the one-run choreography probe and fast correctness gate before capture, directs capture to `artifacts/richCardBaseline.raw.json`, and retains that raw artifact for 14 days with any available Playwright report/test-result outputs. CI does not regenerate the checked-in report: after downloading and reviewing the CI artifact, promote/copy the accepted JSON to the tracked `src/performance/baselines/richCardBaseline.raw.json` path before running `npm run perf:report`. The accepted workflow is therefore probe for choreography health, correctness for search/selection honesty, capture for repeated raw evidence, then report from the promoted retained raw evidence.

The raw correctness record distinguishes verified DOM selection from system clipboard copy. Search is measured on the mounted synthetic giant Note. Selection then follows the normal hover and first-click activation path and is observed only when the selected browser text exactly matches a non-whitespace substring rendered by the live contenteditable editor; this avoids misclassifying the passive React Flow subtree's intentional `user-select: none` as a Selection API failure. Clipboard copy remains unavailable because the harness does not invoke or read the system clipboard. Image ingestion/compression is likewise unavailable because the fixture uses prebuilt data URLs and never invokes the production paste-compression path.

## Unit Tests

Timeouts are set once, in `vite.config.ts`, at 30s. Before 2026-08-20 nothing
set them at all, so every test silently inherited Vitest's built-in 5s. Tests
that touch real SQLite stores, stream real archives, or wait on a real process
run for seconds by design, so they passed alone and failed in a full parallel
run: one run failed three at once. That red is worse than a slow test, because
it accuses whichever subject the test names. A signing test that runs out of
time reads as a signing fault, and the next reader hunts a certificate problem
that was never there. Do not add per-test timeouts to work around load. If a
test needs longer than 30s, it is doing something the unit suite should not.
