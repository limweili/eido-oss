# Conventions

Patterns to preserve when changing the active app.

## Naming And Language

| Convention | Evidence | Guidance |
| --- | --- | --- |
| UI says cards/connections, not nodes/edges/graph/compiler | `src/shared/words.ts`; `docs/archive/initial-product-plan/04-canvas-language-and-feel.md`; comments in `Board.tsx`. | React Flow words may appear only at the canvas boundary. |
| User-facing UI strings live in one place | `src/shared/words.ts` comment and imports across cards/modals. | Add generic labels, errors, placeholders, and button text to `words.ts`; keep kind-specific Mod treatment and sentence mechanics in `src/mods/prompt.ts`. |
| Framework terminology is documented | `CONTEXT.md` defines Card/Connection for product language and node/edge for the React Flow boundary. | Keep new UI and docs aligned with the canonical glossary. |
| Internal names can be precise | `gatherConnectedThought`, `runCard`, `saveIdeaBoard`, `RunRecord`, `ConnectionRole` | Prefer domain names over generic UI-library names. |
| IDs are prefixed | `src/shared/ids.ts` returns `${prefix}_${nanoid(8)}`; store calls `newId('card-kind')`, `newId('conn')`, etc. | Use `newId()` for new persisted records. |

## State And Persistence

| Convention | Evidence | Guidance |
| --- | --- | --- |
| Mutations go through store actions | `src/graph/store.ts` action list and `commit()` wrapper. | Avoid direct writes outside tests/dev tooling. |
| Persist through the selected adapter | `src/graph/store.ts` actions feed `profileRendererPersistence` in packaged mode and `makeDebouncedSaver` only in browser development. | New durable mutations use store actions. Do not call the native bridge, SQLite, disk API, or IndexedDB directly from feature/UI code. |
| Content fails closed, settings fail soft | `src/persistence/settingsEnvelope.ts`; `src/graph/boardAiSettings.ts`; strict `validateCard`/`validateBoard`/`validateIdea` in `src/persistence/profileLogicalProjection.ts`; ADR 0040. | Every persisted field is one of three things. A value the canvas, context, or execution projection reads is content and keeps the strict validators. A presentation or preference value that must travel with the Profile is a portable setting: declare it with `defineSetting`/`defineChoiceSetting`, read it with `readSetting`, and store it in the owning record's envelope with a documented default. The envelopes are `Card.meta`, `Board.settings`, `Board.aiSettings` (now a tolerant preference bag, not a strict one), `Idea.settings`, and Profile-level settings. A value that only affects this machine and does not need to travel is a device setting: it goes in the device preference store and never enters the Profile document. Prefer the device setting whenever the value need not travel. Never add a preference key to a strict allowlist, never widen a strict value union for one, and never add a new top-level field to carry one. Follow [`docs/agents/persisting-a-new-setting.md`](../agents/persisting-a-new-setting.md) before persisting a new field. |
| Keep transient UI state out of `SavedBoard` | `GraphState` separates saved board fields from `selection`, `selectedCardIds`, modals, settings. | Only durable graph state belongs in `SavedBoard`. |
| Structural history is replay-friendly | `src/graph/history.ts` defines `HistoryEntry` and reversible action payloads; `store.ts` keeps bounded undo/redo stacks. | Future timeline playback should extend this history format with persistence/checkpoints instead of creating a separate event model. |
| Current Mod documents normalize at load | `src/mods/normalizer.ts` repairs the eleven kind-specific state shapes and stable nested IDs. | Read current Mods through the shared normalizer before the prompt engine or faces consume them; do not add per-caller repair or legacy conversion. Browser-era `Card.mod` payloads drop at the Board-load seam (ADR 0030). |
| Device settings and credentials stay outside Board and Mod-library data | `SETTINGS_KEY = 'eido-v3-settings'` in `store.ts`; `electron/localCredentialStore.ts`; theme preference helpers in `src/ui/theme.ts`; native template records in `profileUtilityHost.ts`. | Keep API keys and appearance preferences out of `SavedBoard` and Portable Export. Packaged API keys use Electron main's versioned device-local files with OS-protected ciphertext and never persist in renderer storage. The isolated renderer never invokes protected storage directly. Browser development keeps a key only for the current session. In packaged mode, Mod templates and stamp provenance come from the Profile, never `localStorage`. |
| Private Profile and browser-development data stay outside Git | `.gitignore`; `electron/profileArtifacts.ts`; `scripts/vite/storagePlugin.ts`. | Use disposable Profile proof roots or `EIDO_DATA_FILE` paths for tests and experiments. Commit only synthetic storage fixtures. |
| Agent clients discover, bound, preview, then commit | `src/persistence/profileAgentGateway.ts`; `electron/eidoCli.ts`; `docs/agents/eido-cli.md`. | Start with bare `eido`/`eido describe`; keep reads item- and byte-bounded; pin every Board mutation to the inspected revision; dry-run before apply; reuse an idempotency key only for the exact same mutation. Deep-Link Card/Idea identity is authoritative and viewport coordinates are hints. |
| Agent attribution is trusted provenance, not caller payload or user undo | `src/graph/cardAuthorship.ts`; `src/persistence/profileAgentCommandPlan.ts`; `src/persistence/profileAgentChangeTrail.ts`; `src/graph/store.ts`. | Bind `client`/`sessionId` after transport admission. Preserve `createdBy`; a user edit changes `lastModifiedBy` and visually adopts the Card. Keep Agent commits out of the GUI undo stack and reverse them with ordinary attributed edits/deletion. |
| Mutable SQLite Profile writes require the installed live owner capability | `electron/installedProfileSession.ts`; `electron/sqliteProfileOwnerCapability.ts`; `electron/sqliteProfileOwnerCoordinator.ts`; `electron/sqliteProfileRevisionStore.ts`. | Electron main resolves the fixed path and one utility owns the coordinator FIFO. Authority is opaque and bound to its exact exclusive sidecar runtime/path/file plus private token/generation; public fields, `ownerId`, PID, heartbeat, route state, and pathname are never credentials. |
| Packaged hydration is apply, acknowledge, then admit | `electron/installedProfileRouter.ts`; `src/graph/profileRendererPersistence.ts`; ADR 0029. | Apply the complete authoritative/rebased projection before exact epoch/revision ACK. Preserve non-active Boards, template changes, and Mod origins; advance the whole applied rolling baseline before the ACK gap; clear both acknowledgement-pending and recovery-required adapter fences before the synchronous ready observer admits the store. Accept that observer on startup and successful recovery. Admission failure stays terminal and must not reopen recovery. |
| Packaged shutdown binds one exact native checkpoint | `electron/profileRendererCheckpoint.ts`; `installedProfileMainSession.ts`; `installedProfileRouter.ts`; `profileUtilityLifecycle.ts`. | Stop admission and confirm the renderer's `{ nativeGeneration, revision }`; the utility then drains, closes the Profile, releases sidecar authority last, acknowledges, and is joined. Terminal uncertainty attempts bounded forced termination/join and must report if that does not complete; never substitute a delay or a second renderer flush. |
| Profile maintenance and recovery retain authority | `SqliteProfileOwnerCoordinator.transitionProfileStorage()` and `recover()` stop admission, drain, close only the Profile, and retain the exact sidecar/capability across replacement. `sqliteProfileRecovery` persists high-water plus operation phase and returns to healthy only after exact closure verification. | Never release/reacquire authority to repair a Profile. Reset only the operation-owned stage DB/WAL/SHM; preserve quarantine and sidecar evidence. Normal close releases the sidecar last and only through the held handle. |
| Profile blob writes share owner admission | `SqliteProfileOwnerCoordinator.applyAssetCommandBatch()` constructs `sqliteProfileBlobStore` behind the same private FIFO; `sqliteProfileRevisionStore` accepts only its opaque prepared asset batch. | Stage, flush, digest-verify, and atomically promote before acknowledging a logical reference. Persist ordered logical IDs and digest metadata only; never persist raw bytes or physical paths, widen `PUBLIC_GATEWAY_COMMAND_NAMES`, or delete final blobs before Portable Export roots exist. Retained verified recovery-generation roots participate in reachability. |

## TypeScript And Imports

| Convention | Evidence | Guidance |
| --- | --- | --- |
| Strict TypeScript | `tsconfig.json` enables strictness and unused checks. | Run `npm run check` before pushing, or `npm run typecheck` alone after non-trivial changes. |
| Type-only imports where applicable | Source uses `import type` throughout `graph`, `brain`, and `canvas`. | Keep runtime imports clean. |
| Relative imports inside the app | Existing source uses relative paths, not path aliases. | Follow the current style unless aliases are introduced intentionally. |
| Tests colocated by domain | `src/brain/*.test.ts`; `src/graph/store.test.ts`. | Put focused unit tests near the behavior they protect. |

## Design System (the visual law)

The design system v1 is approved and canonical (2026-07-17). It governs
every pixel of UI the app renders.

| Convention | Evidence | Guidance |
| --- | --- | --- |
| One rule book | `docs/design/design-system/SYSTEM.md` | Read the relevant section before any UI change. BRIEF.md is the taste summary; IMPLEMENTATION.md the migration plan; PROPOSALS.md the approved function-change scope (P1–P7 + D1–D15, all approved); the folder's README.md maps the whole canon. |
| One token source of truth | `src/ui/tokens.ts` generates the app's `:root` CSS (`virtual:eido-design-tokens.css`), the canvas painter palettes and and the living reference's token region. | Change a token value there and nowhere else; run `npm run design:sync` to regenerate the reference. `npm run ci:design-system` fails while any consumer is stale. |
| Living reference implementation | `docs/design/design-system/eido-design-system.html` (serve via the `design-system` launch config, port 8642) | When SYSTEM.md prose and the reference disagree, the reference's rendered result is the intent; flag the drift. Its token region is generated — edit `src/ui/tokens.ts` instead. |
| Components pick roles/meanings, never values | SYSTEM.md §1.0 (color) and §2.6 (type) | No component names a hex, px size, weight, or tracking. It names a token/role (`--e-*`, label/ui/value…), and the token layer resolves it — this is what makes dark mode and future retunes propagate with zero component edits. |
| Boxed instruments snap to ladders | SYSTEM.md §3.1 (spacing), §3.5 (heights), §3.2 (radii) | New chrome takes an existing step; a new step is a SYSTEM.md change first. |
| Copy follows the copy sheet | SYSTEM.md §9; user-visible strings in `src/shared/words.ts` | One-word chips put detail in tooltips; callouts never repeat state words; running words use the shared pulse without ellipses; forbidden-vocabulary checks audit visible values, not internal identifiers. |

## UI Component Patterns

| Pattern | Evidence | Guidance |
| --- | --- | --- |
| Most thought cards share `CardShell` | `NoteCard`, `AskAiCard`, `ResultCard`, `ModCard`, `GroupCard`, and `ConversationCard` render `CardShell`; `TitleCard` intentionally does not, so it can behave as a label without connection handles. | Put shared card frame behavior in `CardShell`, but keep label-only surfaces out of the standard card chrome. |
| Shared card header controls live in `CardShell` | Title editing, header color/fill, and resize handles are handled there. | Add shared card-frame chrome here unless it is truly card-kind-specific. |
| Shared controls come from the primitive kit | `src/ui/primitives/index.ts`; visual recipes in `src/styles/005-primitives.css`; behavior tests beside the primitives. | Import the public primitive instead of rebuilding its states in a surface. Keep domain/store knowledge out of the kit; preserve callback semantics at the call site. |
| Modal behavior comes from the overlay foundation | `src/ui/overlays/index.ts`; visual recipes in `src/styles/006-overlays.css`; `OverlayProvider` is mounted once in `src/main.tsx`. | Render modal content in `ModalShell`, declare backdrop dismissal explicitly, and drive its `open` prop through `onExitComplete` so the tokenized, inert exit can retire before unmount. Modal-owned Picker/Popover/Tooltip layers inherit the shell's scoped floating destination. Use `useDialogs` for serialized confirm/prompt requests. Do not create another portal root, document key listener, focus trap, or promise queue at a call site. |
| Canvas adapter translates library terms | `Board.tsx` builds React Flow `nodes` and `edges` from graph `cards` and `connections`. | Keep conversion logic near `Board.tsx`. |
| Persistent canvas tools keep one fixed order; selection and connection controls stay contextual | `BottomDock.tsx` renders the stationary Select/Move/Highlighter \| creators \| Undo/Redo bar through `DockKey`, with card-selection actions in its attached tray. `ConnectionEdge.tsx` and `ConnectionPopover.tsx` own the midpoint pill editor for connection controls. | Add board-wide tools only to the persistent bar without changing its established geometry. Add card-selection actions as icon keys in the attached tray, and connection-specific controls to the pill/popover surface unless a broader modal is clearly warranted. |
| Fixed-height cards use the shared auto-grow hook behavior | `useAutoGrow.ts`; card textareas use it with `fixedHeight`. | Preserve textarea behavior when changing card sizing. |

## Brain Patterns

| Pattern | Evidence | Guidance |
| --- | --- | --- |
| Compiler is deterministic | `compiler.ts` uses ordered incoming connections, strength/polarity buckets, no embedding/ranking. | Add automatic ranking only as an explicit product/architecture decision. |
| Mod prompt emission has one owner | `src/mods/prompt.ts` supplies `readModContext`; `src/brain/modBlock.ts` formats the shared compiled block. | Do not add another prompt formatter or compiler branch for a Mod kind. A kind owns its treatment and sentences; every consumer reads that same context. |
| Avoid is anti-context, not constraints | `compiler.ts` emits `ALREADY EXPLORED — do not retread`; ADR 0018 retires the old constraints section for negative connections and keeps optional reasons with Avoid paths. | Do not blend `pushesAgainst` into `BUILD ON` or `INFLUENCES`; do not reintroduce a hard-constraints bucket for negatives. Hard requirements are ordinary connected notes. |
| Mods speak through one ordered block | `renderModsBlock` emits each connected Mod's treatment immediately followed by its sentences in one `MODS` block. | Preserve connection order and repeated kinds; do not deduplicate treatments, revive target buckets, or treat Mod Cards as ordinary notes (ADR 0030). |
| Who runs the tool loop is decided by the key, not by the code path | `src/brain/agenticRun.ts` owns the concept. With a Linkup key on OpenRouter, Eido runs the loop and executes the tools itself (ADR 0036). With no Linkup key, `openRouter.ts` declares server tools the provider executes inside one completion (ADR 0033, unchanged). `aiProvider.ts` sends a local harness nothing new at all. | Three executors, one concept. Nothing is appended to the compiled instruction on any path, so `compiler.ts` and its golden tests stay untouched: "same graph, same instruction" is a promise about the graph. Never write a tool instruction into a harness prompt to simulate what a provider cannot do. The provider-executed path is the fallback and stays live for every user without a Linkup key, which is what keeps it trustworthy. |
| Eido pins what is not a retrieval decision, and nothing else | `src/brain/webTools.ts` declares `search_web`, `fetch_page`, and (in Research mode) `research` as function tools whose parameters the model fills. Eido pins `outputType` only. | The model chooses search tier, domain and date filters, fetch mode, research mode and reasoning depth, from tool descriptions carrying Linkup's own selection rules (ADR 0036, ADR 0037). Do not move a retrieval choice back into Eido to make a run cheaper: cost is not a constraint here. Do keep the per-result character cap and the prompt reserve, which are the size of the container and not spending limits. |
| Link previews and AI web tools run through separate boundaries | `electron/linkPreviewService.ts` loads public page metadata and preview assets. `src/brain/linkup.ts` owns keyed search, page fetch, and research. | Keep previews keyless and independent of AI. A Run can use the optional Linkup key or the AI provider's existing web tools. Map provider errors to known codes and use `words.ts` for user-facing copy. |
| Version context is frozen | `VersionContext.tsx` reads the original run record rather than recomputing. | Preserve this for provenance. |
| Run provenance snapshots applied Mods | `RunRecord.appliedMods` records control values and emitted instructions, including silent controls' values. | Later Mod edits affect future runs, never rewrite an existing version's provenance. |
| Conversation runs separate private and shared context | `conversationCompiler.ts` resolves each Ask AI participant's private context separately from Conversation-level shared context. | Do not leak one participant's incoming notes into another participant's prompt. |
| Transcripts are data, not rendered-only text | `TranscriptMessage` in `src/graph/types.ts`; pure helpers in `src/brain/transcript.ts`; `ConversationResultCard.tsx` renders transcript versions. | Update transcript helpers/store actions when changing Conversation behavior. |
| Delegated Agent Runs use the ordinary live execution path | `src/brain/agentRunSession.ts`; `src/brain/agentRunExecutor.ts`; `src/desktop/agentRunExecutionAdapter.ts`; `src/desktop/profileAgentRunRendererService.ts`; `src/desktop/profileAgentRunRendererRuntime.ts`; `electron/profileAgentRunLiveService.ts`. | Keep submit/status/read live-app-only; admit only active-Idea OpenRouter-backed Conversations and non-Agentic Ask chains with bounded variations; refuse device-local harness commands and unbounded Agentic loops; reuse fresh upstream Ask steps; budget every Ask, Group refresh, Conversation turn, and uncached compaction before start; execute only the explicit admitted schedule; and expose bounded record references rather than caller-controlled execution settings, model output, or credentials. `submit-outcome-unknown` is nonretryable because admission may already have happened. Stop admission, cancel/drain accepted execution and flushes, then take the final renderer checkpoint on authority loss or quit. |

## Error Handling

| Pattern | Evidence | Guidance |
| --- | --- | --- |
| AI errors collapse to plain message keys | `runEngine.ts` `plainError()` returns keys like `errCouldNotReach`; UI resolves via `words`. | Keep stack traces/details out of user-facing UI. |
| OpenRouter HTTP/key failures throw `AiError` | `openRouter.ts`. | Catch at the run engine boundary, not inside card components. |
| Failed runs remove placeholder versions | Store `failRun()` filters out the produced version and records failed status. | Keep output stacks clean when runs fail. |
| Canceled Ask AI and Group compression runs keep provisional versions | Store `cancelRun()` marks the produced version provisional and preserves streamed text. | Treat user stop/cancel as a draft, not as a failed run. |
| Failed/canceled Conversation runs keep provisional versions | Store `failConversationRun()` and `cancelConversationRun()` mark the version provisional and preserve the transcript. | Do not apply plain Ask AI failure cleanup to Conversation runs. |
