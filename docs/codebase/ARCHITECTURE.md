# Architecture

The active architecture is a local-first React app with one saved property graph. Canvas, semantic context, and execution are projections over that graph ("one graph, three views" - ADR 0011). Per-layer seams, invariants, and roadmaps live in `docs/foundations/`.

## Boundary Rules

| Rule | Current evidence | Agent guidance |
| --- | --- | --- |
| Graph core should stay canvas-agnostic | `src/graph/**` imports app helpers/types but not `@xyflow/react`; `Board.tsx` comment says React Flow jargon is translated at the boundary. | Keep React Flow-specific terms in `src/canvas/`. |
| AI egress stays behind an explicit provider boundary | `src/brain/aiProvider.ts` selects user-owned OpenRouter BYOK or the main-process local-harness bridge. Web tools use a supplied Linkup key or supported provider web search. No Eido-funded credential or control plane participates. | New providers preserve ordinary run-engine provenance, cancellation, and asset seams. |
| Local harness shutdown is joined | `electron/aiHarnessMainSession.ts` owns active process groups/trees and bounded settlement; `electron/main.ts` awaits it on normal quit and fatal shutdown. | Never release a local harness bridge synchronously while child or descendant processes may still be running. Stop admission, cancel, escalate, and join first. |
| User-facing UI copy belongs in `src/shared/words.ts`; Mod behavior belongs in the Mod module | `words.ts` holds shared labels/errors/placeholders; `src/mods/faces/registry.ts` and `src/mods/prompt.ts` own each kind's interaction and prompt semantics. | Keep generic UI strings in `words.ts`; extend the Mod registry and prompt seam together when adding a kind. |
| Runs and output versions are provenance objects | `RunRecord.compiledInstruction`, `RunRecord.conversation`, `usedCardIds`, `usedConnectionIds`; `VersionContext.tsx`. | Do not write generated text only into a card block. |
| Result follow-ups use frozen provenance | `followUpRunner.ts` builds follow-up prompts from `OutputVersion.fromRunId` and `RunRecord.compiledInstruction`, not by recompiling the current board. | Keep follow-up threads attached to their output version. |
| Conversation public transcript and private context stay separate | `conversationCompiler.ts` resolves participant private context through `gatherConnectedThought()` and shared Conversation context separately. | Keep participant backstage context out of other participants' prompts. |
| Title cards are labels, not thought context | `TitleCard.tsx` renders without `CardShell` handles; store `addConnection()` rejects title endpoints; compilers skip title sources. | Do not include title labels in grouping, connection, or AI-context behavior unless the product grammar changes. |
| A Title card is type sized by its box, at every zoom | `titleCardFontFit.ts` fits the DOM editor to the drawn card; `titleCardCanvasText.ts` paints the same fit at board scale; `BoardOverviewLayer.tsx` gives the kind no card body and keeps it out of the label layer. | Do not give a Title card paper, ports, or a fixed-size painted label. A change to the fit rule must move both halves together. |
| Packaged Eido has one installed Profile authority | `profileInstallation.ts` fixes the path; `main.ts` acquires the singleton and starts one utility only after readiness; `installedProfileSession.ts` constructs authority; `installedProfileMainSession.ts` owns trusted main-frame routing and checkpointed shutdown; `installedProfileRouter.ts` owns one FIFO and joined close. | Never open the production Profile in renderer or Electron main-loop code, derive its path from branding, or create a second writer/provider. |
| Preload bridges are logical, narrow, honest, and fail-closed | `profileBridgeContract.ts` and `keychainBridgeContract.ts` expose disjoint allowlists over separate versioned channels; `profileAgentRunBridgeContract.ts` carries only bounded Run request/result frames; `security.ts` requires the same exact owned `eido://app` main frame. Profile and Run payloads omit credentials, owner authority, paths, provider keys, and model output; credential payloads expose no paths or storage details. | Advertise only end-to-end callable operations and keep capabilities, contracts, routers, and handlers in lockstep. Fail closed on version, identity, sequence, correlation, frame, or hydration drift; never expose raw IPC, SQL, generic records/patches, credential files, or browser fallback for packaged origins. |
| Renderer authority changes only after actor install/apply/ACK/admit | `installedProfileRouter.ts` issues an epoch/revision guard and carries one bounded session actor beside the snapshot; `profileRendererPersistence.ts` validates and pins it before installing or safely rebasing complete projection state, ACK, and native-queue reset. | Preserve non-active Boards, template changes, exact Mod origins, and exact historical Intent prefixes across lifecycle handoff. Advance the whole applied rolling base before the ACK gap; exact ACK must clear both acknowledgement-pending and recovery-required adapter fences before synchronous readiness. Accept the ready observer on startup and successful recovery; keep admission failure sticky terminal rather than reopening recovery. |
| Mutable native authority stays private and owner-held | `sqliteProfileOwnerCoordinator.ts` owns canonical/physical identity checks, the exact held sidecar, opaque capability and private fence, one FIFO, drain, and maintenance handoff. | Never trust caller-supplied token/generation fields, `ownerId`, PID, heartbeat age, or a path string as authority, and never release an owner by reopening its path. |
| Content-addressed blobs remain owner-gated and non-destructive | The utility coordinator alone admits prepared asset batches; live, historical Intent, retained recovery, and Portable Export roots share verified content-addressed finals. | Keep paths and raw bytes out of records, receipts, events, and diagnostics. Missing or corrupt reachable bytes require recovery; unreferenced finals remain healthy candidates until a complete deletion policy exists. |
| Recovery remains owner-held and bounded | Recovery-required mode retains the exact sidecar/capability while the typed renderer bridge admits only candidate inspection and restore; recovery-only close remains a main-owned shutdown operation. | Never expose paths, SQL, sidecar fields, or operation IDs. Rejected candidates remain inspection evidence; bound-Profile corruption or physical-identity loss enters recovery-required while sidecar-fence loss is terminal. Failed renderer admission does not reopen recovery. |
| Portable lifecycle stays behind named operations | The native owner implements `exportPortable`, `importPortableIntoFreshProfile`, `duplicateIdea`, and `importIdeaClosure`; the active packaged bridge advertises only export, Duplicate, and current-Idea import, while fresh full import remains bootstrap-owner-only. | Preserve deterministic archive/remap evidence and opaque sources; never add a generic record/patch surface. Incoming mismatch is invalid input, while corruption of already reachable authority requires recovery. |
| One bounded Agent Gateway serves adapter-filtered transports | `profileAgentGateway.ts` derives static CLI discovery and dispatch from one descriptor registry with per-operation adapter and availability metadata. `describe` acquires no authority. MCP projects exactly seven tools; standalone `eido` additionally exposes CLI-only spatial/history/Run operations. Existing-only headless sessions single-flight one lease and drain before close; the live app route is same-user/tokened local IPC and globally serialized with renderer persistence. | Keep all adapters on the descriptor/planner seam.
