Lesson 0001

Scalability Is Not One Thing

Your founder job is not to ask agents for "production-grade scalability." Your job is to name which kind of scale pressure the feature creates.

One sentence to remember: mature repos scale by turning expensive questions into explicit projections, indexes, run records, or service boundaries.

The Five Scalability Lenses

Editor State

tldraw: many records and relationships stay responsive through typed stores, migrations, bindings, culling, and incremental derivations.

Render Simplicity

Excalidraw: the canvas feels fast because the scene, static render, interactive overlay, and restore path are kept simple.

Execution

n8n: the authored workflow is separate from run data, waiting state, execution stack, partial runs, and item lineage.

Graph Meaning

Neo4j: relationships have direction, type, and properties. The edge is not decoration; it is a queryable object.

System Boundary

Penpot: expensive, collaborative, or operational work moves into workers, backends, pub/sub, storage, async tasks, and exporters.

How They Differ

tldraw and Excalidraw both care about canvas feel, but they make different bets. tldraw is deeper: a reactive document store, shape utilities, binding utilities, schema migration, and derived indexes. Excalidraw is lighter: scene maps, visible element filtering, a static canvas, an interactive canvas, and repair on restore.

n8n and Neo4j both use graphs, but the word "graph" means different things. n8n's graph is operational: what runs, waits, resumes, retries, and produces data. Neo4j's graph is semantic: what connects, what kind of relationship it is, what properties the relationship carries, and how traversal should answer a question.

Penpot is the reminder that product scale eventually becomes system scale. Once Eido needs teams, sync, exports, background AI work, or hosted collaboration, some work should leave the main browser thread and some should leave the browser entirely.

The Eido Rule

Eido should keep one property graph with three projections:

Canvas View

Cards, positions, selection, zoom, culling, edge drawing, hit testing, and text editing.

tldrawExcalidraw

Semantic View

Context compilation, edge weight, polarity, constraints, relevance, and explanations.

Neo4j

Execution View

Runs, output versions, graph snapshots, partial re-runs, waiting state, and provenance.

n8n

That is why the canvas must not become the graph database. It should render the graph. The compiler should query the graph. The run engine should execute against graph snapshots. The persistence layer should retain the pieces with different lifetimes.

Practice

Choose the architecture bucket. The option names are intentionally short; the feedback is where the teaching lives.

A new feature scans all Connections on every card drag.
An output version should explain what generated it and be re-runnable.
The compiler must know whether a relationship supports or contradicts a note.
Exporting a large board freezes the editing surface.

How To Talk To Agents

Do not say only: "make this scalable." Say this:

For this feature, first identify:
- the hot path, if any
- the Board records read and written
- the source of truth
- the derived index, scene projection, run record, or worker boundary
- the performance gate that proves the design at 5,000 Cards and 10,000 Connections

Then add the product constraint:

Preserve Eido's one graph, three views model. The canvas renders the graph; it is not the graph database.
