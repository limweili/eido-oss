Lesson 0002

One Graph, Three Projections

The skill today: decide whether a feature belongs in Eido's source of truth or in one of its projections.

Founder rule: if two parts of the app can disagree about reality, agents have accidentally created two products.

The Shape

Eido v3 already states the architecture plainly: one property graph, with the canvas, context compiler, and run engine as projections of it. In code, the source of truth is the saved Board: Cards, Connections, Outputs, Runs, Intent Log Events, and settings.

Graph Truth

Board records: cards, connections, outputs, runs, timeline events.

Canvas View

What is visible, selectable, culled, summarized, and drawn.

Semantic View

What context matters, what constrains, and what modifies the task.

Execution View

What ran, which model was used, what inputs were included, what version was produced.

Playback View

What meaningful board state existed at a selected time.

Why This Scales

The architecture scales because each view can optimize its own questions without becoming the owner of truth.

Canvas asks

Which cards and connections should be rendered right now?

boardScene.ts and renderPlanning.ts answer with visible cards, culled IDs, zoom bands, summaries, hit-test candidates, and connection plans.

Semantic asks

What should AI use, ignore, or obey?

compiler.ts turns graph relationships into a structured instruction: important context, also consider, constraints, modifiers, task.

Execution asks

What happened, from what inputs, and what did it produce?

runEngine.ts records runs, used card IDs, used connection IDs, applied Mods, source context, and output versions.

Playback asks

What did the board mean at this time?

timeline.ts projects board state from coarse intent events and checkpoints, rather than replaying every keystroke.

The Mistake To Catch

The most dangerous implementation smell is a feature that stores meaning only inside a view. Examples:

Smell Why It Hurts Later Better Question
Connection meaning lives only in edge color. The compiler cannot reliably know whether an edge supports, contradicts, feeds, or modifies. What property on Connection owns the meaning?
AI output is just text in a card. You lose which run, model, context, and graph version produced it. What RunRecord and OutputVersion prove provenance?
Playback reuses undo history. Undo wants short, fast memory. Playback wants durable semantic reconstruction. Should this be Undo, Intent Log Event, both, or neither?
Canvas code scans the whole Board on pan. Hot paths become slower as the user's thinking grows. What render index or scene projection should answer this?

The Agent Review Move

When an agent proposes a feature, ask for a placement map before accepting the implementation:

Feature placement:
1. Graph truth: which Board records own the durable meaning?
2. Canvas view: what is merely visual or interactive?
3. Semantic view: does this affect context compilation?
4. Execution view: does this affect runs, provenance, or output versions?
5. Playback view: does this create or consume Intent Log Events?

If an agent cannot fill this in, the implementation is probably about to blur boundaries.

Practice

Pick the owner. Each scenario has one best first home; other views may project from it later.

A connection now means "this note contradicts that note."
At far zoom, cards should become compact summaries.
AI should treat negative links as constraints, not examples.
An output must remember which model and context produced it.
